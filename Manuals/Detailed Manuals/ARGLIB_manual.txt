ARGLIB – Argument handling library for R65 Pascal
=================================================

NAME
----
ARGLIB – R65 Pascal library to access program arguments

SYNOPSIS
--------
```
program test;
    uses arglib;
    var value, cyclic, drive: integer;
        s: array[15] of char;
        def: boolean;
begin
    _carg := 0;
    { read next integer argument }
    _agetval(value, def);
    { read next string arg }
    _agetstring(s, def, cyclic, drive);
    writeln(value, ' ', s, ' ', cyclic, ' ', drive);
end.
```

DESCRIPTION
-----------
**ARGLIB** provides access to the system‑supplied
argument list when a Pascal program is executed.  It
interprets the arrays maintained by the monitor
(NUMARG, ARGLIST, ARGLISTS, ARGTYPE) and offers
routines to retrieve integer and string parameters
without having to know the internal storage layout.
Filenames can be prepared for use with the system file
manager via `_asetfile`.

When the main program starts, the global variable
`_carg` is set to 0. Each call to `_agetval` or
`_agetstring` advances `_carg` and extracts information
from the monitor‐maintained arrays.

SYSTEM VARIABLES
----------------
The library uses several memory‑mapped variables to
communicate with the operating system.  These variables
are defined in the `mem` section of `arglib` and should
not be modified directly by user programs.

* `NUMARG` (integer @$005F)

  The number of arguments passed on the command line
  by the monitor.

* `ARGLIST` (array[10] of integer @$0060)

  List of up to ten 16‑bit integer arguments.  Each
  entry corresponds to an argument of type `'i'` or
  `'d'` in the `ARGTYPE` array.

* `ARGLISTS` (array[63] of char @$0060)

  Packed list of string arguments.  Each string
  occupies eight characters; arguments of type `'s'`  
  are retrieved from here.

* `ARGTYPE` (array[31] of char @$00A0)

  Type descriptor for each argument.  Valid codes are
  `'i'` (integer), `'s'` (string), `'d'` (default).
  A zero byte indicates the end of the argument list.

* `FILFLG` (integer @$00DA)

  File flag used by `_asetfile` to control file system
  behaviour.  Bit 6 (`$40`) suppresses file display
  in directory listings.
 
* `FILDRV` (integer @$00DC)

  Current device number for file operations set by
 `_asetfile`.

* `FILCYC` (integer @$0311) and `FILCY1` (integer
  @$0330) Cycle numbers used for sequential files
  created by `_asetfile`.

* `FILNAM` (array[15] of char @$0301) and `FILNM1`
  (array[15] of char @$0320)

  Primary and secondary file name buffers.  `_asetfile`
  writes the upper‑cased filename into these arrays.

* `FILSTP` (char @$0312)

  File subtype set by `_asetfile` when a colon and 
  subtype letter appear in the filename.

* `_carg` (integer)

  Internal index used by ARGLIB to track which argument
  is being processed.  It is initialised to 0 at
  program startup.

PROCEDURES AND FUNCTIONS
------------------------
* `proc _argerror(e: integer);`

  Prints `Argument error <e>` on the console, sets the
  global `RUNERR` to 255, and terminates the program
  via a system call.  Used by the argument routines on
  invalid type codes.

* `proc _agetval(var value: integer;
        var default: boolean);`

  Reads the next argument from `ARGTYPE[_carg]`.  If
  the type is `'i'`, the corresponding entry in
  `ARGLIST` is returned in `value` and `default` is
  set to *false*.  If the type is `'d'` or the argument
  list has ended, `default` becomes *true*, `_carg`
  is advanced and `value` remains unchanged.  On
  invalid type codes `_argerror(102)` is invoked.

* `proc _agetstring(var string: array[15] of char;
        var default: boolean;
        var cyclus, drive: integer);`

  Retrieves a string argument.  If `ARGTYPE[_carg]` is 
  `'s'`, eight characters are copied from `ARGLISTS`
  starting at position `2 * _carg`, the `_carg` counter
  is increased by eight, and `default` is set to
  *false*.  If the type is `'d'` or the list is
  exhausted, the `string` is filled with blanks and
  `default` becomes *true*.  After returning the
  string, `_agetval` is called twice to fetch the cycle
  number and device number into `cyclus` and `drive`.
  Invalid type codes cause `_argerror(101)`.

* `func _uppercase(ch: char): char;`

  Returns the uppercase version of `ch` if it lies
  between `'a'` and `'z'`; otherwise the character is
  returned unchanged.  Used by `_asetfile` when
  building file names.

* `proc _asetfile(name: array[15] of char;
  cyclus, device: integer; subtype: char);`

  Prepares file parameters for monitor file operations.
  It uppercases the input `name` and stores it into 
  both `FILNAM` and `FILNM1`.  If `subtype` is
  non‑blank and a colon appears in the name, `FILSTP`
  is set to the subtype character and the colon
  followed by the subtype is inserted.  The cycle and
  device numbers are stored into `FILCYC`/`FILCY1` and 
  `FILDRV`, and `FILFLG` is set to `$40` to suppress
  directory output.
